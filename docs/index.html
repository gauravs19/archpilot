Methodology

The Spec-Driven Development Loop

Archpilot encodes the Specify → Plan → Task → Implement workflow — the same discipline used in AWS Kiro and GitHub Spec Kit — as a set of rules, templates, and AI instructions that any team can adopt in minutes.

01
Specify

Capture business intent in machine-readable EARS notation. Unambiguous, testable, traceable.

requirements.md
02
Plan

Translate specs into component design, data models, API contracts, and ADRs.

design.md
03
Task

Decompose design into atomic, independently verifiable units. Each task ≤ 4 hours.

tasks.md
04
Implement

AI agents execute one task at a time, constrained by the spec and project constitution.

constitution.md

Spec-Kit — New in Phase 6

From "Vibe Coding" to Verifiable Engineering

Spec-Driven Development treats the specification as the primary source of truth. Code becomes a derivative artifact — regenerable, verifiable, and always aligned with the approved design.

📋

EARS Notation

Easy Approach to Requirements Syntax transforms vague prose into machine-parseable, test-mappable behavioral statements — five precise patterns, zero ambiguity.

🔗

Requirement Traceability Matrix

Every EARS requirement maps to a design component, an implementation task, and a test. No requirement ships untested. No code ships unspecified.

🤖

Agent-Ready Context Loading

The Spec-Kit triad is structured for minimal, precise context injection — constitution first, single task second, relevant design sections third. No full-codebase hallucination.

      retry 3x with exponential backoff |

## Security Non-Negotiables

- [ ] No hardcoded secrets — use Secrets Manager
- [ ] JWT validation on every protected endpoint
- [ ] Parameterized queries only — no SQL concat
- [ ] No PII in logs — automated scanner in CI

## AI Agent Boundaries

Agents MUST NOT modify migration files without
DBA review or commit to main branch directly.

EARS Pattern Reference

Five sentence patterns that make every requirement unambiguous, testable, and directly mappable to implementation tasks.

PatternTemplateExample
UbiquitousThe [system] shall [action].The Payment Service shall use TLS 1.3 for all inter-service communication.
Event-DrivenWhen [trigger], the [system] shall [action].When a user submits valid credentials, the Auth Service shall issue a signed JWT within 200ms.
State-DrivenWhile [state], the [system] shall [action].While the mobile app is offline, the system shall queue operations and sync on reconnection.
UnwantedIf [condition], then the [system] shall [action].If the Payment Gateway returns 5xx, then the service shall retry 3 times with exponential backoff.
OptionalWhere [feature enabled], the [system] shall [action].Where multi-tenancy is enabled, the API shall enforce tenant-scoped data access on every request.

Quick Start

Up and Running in 2 Minutes

Choose your platform. No installation. No CLI. No build step. Copy, paste, and your LLM immediately operates at enterprise-architect level.

# Option A: Claude Projects (Recommended)

1. Create a new Claude Project
2. Paste llm-configs/claude-project-instructions.md
   as custom instructions
3. Upload as project knowledge:
   rules/00-architecture-principles.md
   rules/04-lld-standards.md
   rules/27-spec-driven-development.md
   templates/spec-template.md
4. Ask: "Create a spec for a payment service
   using EARS notation."
5. Get production-grade output ✓
# Option B: AWS Kiro (Native SDD)

# Place file in your project:
.kiro/steering/archpilot-standards.md

# Copy from:
llm-configs/kiro-steering-instructions.md

# Kiro will automatically enforce:
✓ EARS notation on requirements
✓ Specify → Plan → Task → Implement loop
✓ Constitution constraints on every task
✓ Security non-negotiables in every file
✓ API-First workflow before implementation
# Option C: Cursor IDE

# Copy to your project root:
cp llm-configs/cursor-rules.md .cursorrules

# For spec-driven projects, also add:
mkdir -p .specs
cp templates/spec-template.md .specs/requirements.md
cp templates/design-spec-template.md .specs/design.md
cp templates/task-list-template.md .specs/tasks.md
cp templates/constitution-template.md constitution.md

# Open a composer session and say:
"Implement Task T-03 from .specs/tasks.md.
Follow constitution.md. Reference
.specs/design.md §3 for data models."
# LLM-Agnostic: Prefix-Any-Prompt Pattern

# For any LLM (Gemini, Groq, Claude, GPT-4):

"Follow these architecture standards:
[paste rules/27-spec-driven-development.md]

Now convert these user stories to EARS notation
and produce requirements.md for a real-time
fraud detection service. Include:
- Functional requirements (FR-001..)
- NFRs with numeric targets
- Acceptance criteria for each FR
- RTM stub
- Out of scope section"
